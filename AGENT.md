# nextjs-template — Agent Instructions

This is the Next.js frontend theme for a Dendron-published static site (the `sotoy` knowledge base). It renders note content generated by `dendron publish` into a navigable web UI.

## Stack

- **Next.js 12** with TypeScript
- **React 17** + Ant Design 4
- **Routing**: `pages/index.tsx` (root) + `pages/[...slug].tsx` (all other notes)
- **Data**: static JSON files written by `dendron publish` into `data/`
- **Styling**: Sass + Ant Design themes

## Repo layout

```
components/   React components (all prefixed DendronXxx)
pages/        Next.js pages — index.tsx and [...slug].tsx
utils/
  build.ts        Data loaders for notes, slugs, config (used at build time)
  links.ts        URL/path helpers
  hooks.ts        React hooks (search, navigation)
  getStaticPropsUtil.tsx  getStaticProps for the root index page
context/      React context providers
types/        Shared TypeScript types
styles/       Global Sass stylesheets
env/          Server-side env validation (env/server.ts)
scripts/      Sitemap generation
data/         Generated at publish time — do not edit manually
public/       Static assets
```

## Routing rules

- `pages/index.tsx` — serves `/` using the Dendron `noteIndex`
- `pages/[...slug].tsx` — serves all other routes; slug maps to `note.fname.split(".")` (dots become path segments)
- `pages/refs/[id].tsx` — note reference panels
- Do **not** use `[[...slug]].tsx` (optional catch-all); it conflicts with `index.tsx`

## Key utilities (utils/build.ts)

| Export | Purpose |
|---|---|
| `getNotes()` | Returns `{ notes, noteIndex }` from `data/notes.json` |
| `getNoteBySlugPath(slug)` | Looks up a note by `string[]` slug |
| `getNotePaths()` | `getStaticPaths` — lists all note slugs |
| `getNoteBody(id)` | Reads rendered HTML from `data/notes/{id}.html` |
| `getNoteMeta(id)` | Reads note metadata |
| `getConfig()` | Reads `data/dendron.config.json` |

## Development

```bash
# from the sotoy root
make dev       # runs dendron publish dev --dest .next (starts Next.js dev server)
make build     # production build
make install   # npm install inside nextjs-template
```

Or directly:
```bash
cd nextjs-template
npm run dev    # Next.js dev server on :3000
npm run build
```

## Code conventions

- All components are functional React with TypeScript.
- Component files are named `DendronXxx.tsx` and live in `components/`.
- Avoid importing between `pages/` files; shared logic lives in `utils/` or `components/`.
- Import paths from `pages/` should use `../` (one level up), never `../../`.
- Do not add new optional catch-all routes (`[[...slug]]`) that overlap existing pages.
- Keep `data/` read-only at runtime; all data is written by `dendron publish`.

## Environment variables

Defined and validated in `env/server.ts`:

| Variable | Default | Purpose |
|---|---|---|
| `NEXT_PUBLIC_ASSET_PREFIX` | (none) | CDN/basePath prefix in production |
| `BUILD_DIR` | `.next` | Next.js build output directory |
| `DATA_DIR` | `data` | Dendron-generated data directory |
| `PUBLIC_DIR` | `public` | Static assets directory |
